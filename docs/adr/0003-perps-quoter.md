# ADR-0003: Perps Quoter — окремий процес з власним транспортом через egress-проксі

**Status:** Accepted (реалізовано; live-перевірка власником акаунта не виконувалась)
**Date:** 2026-10-19
**Deciders:** власник акаунта (live-запуск, юрисдикція, розміри), розробка (архітектура)

## Context

Потрібен котирувальник для програми Liquidity Rewards Polymarket Perps за специфікацією [`perps-quoter-architecture.md`](../../perps-quoter-architecture.md) і калькулятором дохідності. Він має працювати цілодобово, без відкритої вкладки браузера.

Сили, що впливають на рішення:

- **Мережа.** 2026-10-19 з цієї машини прямий запит до `api.perpetuals.polymarket.com` не встановлює з'єднання (HTTP 000). Через надані HTTP-проксі в Німеччині та Польщі REST відповідає 200 за ~0.45–0.6 с, WebSocket працює. За 3 хв заміру одне з трьох тунельних WS-з'єднань обірвалося (1006).
- **SDK.** У `@polymarket/client@0.13.0` немає modify. Явного налаштування проксі для його WebSocket не знайдено (не перевірено). ADR-0001 уже реалізував офіційний підпис (MessagePack + EIP-712) без SDK.
- **Ключі.** ADR-0002 тримає proxy-ключі лише в пам'яті браузера. Headless-процесу потрібне інше джерело, але без запису секретів у файли.
- **Гео-обмеження.** Розміщувати ордери заборонено з US, CA, CU, IR, KP, SY, Криму, Донецької й Луганської областей. Документація вимагає блокувати подачу ордерів, а не лише попереджати. Ринкові дані не обмежені. Проксі не змінює юрисдикцію оператора.
- **Правила проєкту.** Один підписаний запис = одна спроба, транспортна невизначеність потребує звірки. Paper/dry-run без доступу на запис. Жодних live-угод під час розробки.

## Decision

1. `quoter/` — окремий Bun-процес із CLI (`probe`, `dry-run`, `status`, `run --live`, `cancel-all --live`). Зовнішнього HTTP-сервера немає, є лише локальна панель (п. 7). Залежності беруться з кореня: viem, @msgpack/msgpack, decimal.js. YAML читає `Bun.YAML`. Нових пакетів немає.
2. Увесь REST і WSS іде через `EgressPool`: Bun `fetch(url, {proxy})` і `new WebSocket(url, {proxy})`. На старті пул вимірює всі маршрути через `/v1/info/time` і вибирає найшвидший. Читання й потоки перемикаються на інший маршрут при збоях. **Підписаний запис робить рівно одну спробу на поточному маршруті, без failover.** Невизначений результат блокує нові записи до REST-звірки.
3. Публічні дані надходять двома дубльованими потоками через різні проксі. Дублікати відкидаються за глобальним `sq`, тож обрив одного тунелю не робить стакан застарілим.
4. Ордери: post-only GTC, перестановка через `modifyOrdersCOID` (власний підписувач). Створення, скасування, `cancelAll`, `autoCancel`, `updateLeverage` — підписаний REST за офіційними compact-формами.
5. Облікові дані беруться лише з оточення процесу: або `PERPS_OWNER_PRIVATE_KEY` (на старті реєструється proxy-ключ із TTL, owner-ключ одразу видаляється з env), або вже зареєстрований proxy key + secret. `quoter/.env` приймає лише `QUOTER_*`-ключі й відхиляє будь-які `*PRIVATE_KEY*`/`*SECRET*`.
6. Live-режим вимагає `mode: live`, прапорець `--live` і декларацію `operator.jurisdiction`/`region`. Країни й регіони з офіційного списку блокуються до будь-якого підпису.
7. Локальна панель (`127.0.0.1:4320`) показує стан процесу й має одну дію, Stop. Захист такий самий, як у PolyTrade: loopback Host/Origin і контрольний токен процесу.
8. **Доповнення 2026-10-20: кілька активів.** Один процес котирує довільний набір інструментів на одному акаунті. Облікові дані, приватний потік, `autoCancel`, бюджет дій, денний ліміт і публічні сокети спільні. Стакан, ордери, ризикові таймери, метрики й цикл окремі для кожного активу (`InstrumentQuoter`). Активи можна додавати й знімати з панелі (токен і підтвердження); вибір зберігається в `data/selection.json`. Альтернатива «окремий процес на актив» відкинута: кілька процесів конкурували б за один акаунтний `autoCancel` і бюджет дій.

## Options Considered

### Option A: власний транспорт + egress-пул (обрано)
| Dimension | Assessment |
|---|---|
| Complexity | Medium: WS-сесії, підпис, звірка написані вручну |
| Cost | Без нових залежностей; трафік через платні проксі |
| Scalability | Один інструмент на процес; кілька процесів на різних інструментах |
| Team familiarity | High: той самий підпис і стиль валідації, що в ADR-0001/0002 |

**Pros:** кожен запит гарантовано йде через проксі; modify доступний; поведінку повторів контролюємо самі.
**Cons:** зміни протоколу треба відстежувати самостійно; private-WS `sq`-семантика не перевірена наживо.

### Option B: офіційний SDK `@polymarket/client`
| Dimension | Assessment |
|---|---|
| Complexity | Low для place/cancel, але modify все одно власний |
| Cost | Нова залежність, `engines: node >= 24` |
| Scalability | Та сама |
| Team familiarity | Low |

**Pros:** менше коду для сесії та стрімів.
**Cons:** немає явного проксі для WS (не перевірено), прихована логіка повторів суперечить правилу однієї спроби, modify все одно потрібен окремо.

### Option C: розширити браузерного бота з ADR-0002
| Dimension | Assessment |
|---|---|
| Complexity | Medium |
| Cost | Немає |
| Scalability | Low: вкладка має бути відкрита й активна |
| Team familiarity | High |

**Pros:** ключі лише в браузері.
**Cons:** не працює 24/7. Uptime, від якого залежить винагорода, падає, коли вкладка засинає.

## Trade-off Analysis

Винагорода лінійно залежить від uptime, тож вирішальними є безперервна робота й контроль над мережею. Тому B і C відпадають. A коштує більше коду, але дає дві гарантії, які не забезпечує SDK: жоден запит не йде повз проксі, і жоден підписаний запис не повторюється неявно. Ключ власника в env на старті — компроміс заради headless-роботи. Його пом'якшують коротший TTL proxy-ключа, видалення owner-ключа з env після реєстрації та режим готового proxy-ключа, у якому owner-ключ процесу взагалі не потрібен.

## Consequences

- Простіше: dry-run на живих даних без ключів; метрики score/uptime у JSONL; повний live-шлях перевіряється проти локальної мок-біржі з реальною перевіркою підписів.
- Складніше: обриви тунелів через проксі потребують моніторингу. Затримка ~0.5 с на запис обмежує частоту перестановок.
- Переглянути після першого live-запуску: семантику private `sq` (поточна реакція: rate-limited REST-звірка), реальне резервування маржі протилежними лімітками, денний ліміт `autoCancel`, появу modify в SDK.
