# Perps Quoter

Котирувальник для [Liquidity Rewards](https://docs.polymarket.com/perps/liquidity-rewards) Polymarket Perps. На кожному вибраному активі (PLTR, NVDA, BTC тощо, будь-який інструмент біржі) він тримає post-only GTC ордери з обох боків від mid у діапазонах 0–5 / 5–10 / 10–20 bps і переставляє їх через modify. Специфікація: [`../perps-quoter-architecture.md`](../perps-quoter-architecture.md). Рішення: [ADR-0003](../docs/adr/0003-perps-quoter.md).

Увесь трафік до API (REST і WebSocket) йде через HTTP-проксі з `QUOTER_EGRESS_PROXIES` у `quoter/.env`. Прямого з'єднання немає, доки `egress.allow_direct: false`.

## Команди

```powershell
cd C:\PolyTrade\quoter
bun run probe      # проксі, серверний час, інструменти, публічний WS (лише читання)
bun run dry-run    # живі дані, симульовані сітки й метрики score/uptime, без записів
bun run status     # приватний стан акаунта (потрібні ключі, див. нижче)
bun run start      # live: run --live
bun run cancel-all # скасувати всі ордери на вибраних активах
bun run check      # tsc --strict + тести
```

Опції: `--from-config` ігнорує вибір, збережений панеллю; `--instrument NVDA-USD` обмежує `status` / `cancel-all` одним активом.

## Активи

Список активів задається в `instruments:` у конфігу: символи (`PLTR-USD` або `PLTR`) чи id з `/v1/info/instruments`. Кожен актив використовує спільні `levels`, `inventory` і `leverage`, якщо не має власних (див. закоментований приклад у `config/example.yaml`). Старий формат `instrument: PLTR-USD` теж працює.

Один процес котирує всі вибрані активи на одному акаунті. Спільні для всіх: облікові дані, приватний потік, dead man's switch (`autoCancel` діє на весь акаунт), бюджет дій, денний ліміт збитку та публічні WebSocket-з'єднання. Окремі для кожного активу: стакан, ордери, ризикові таймери (брейкер волатильності, заморозка, розширення після post-only відмов), метрики (`data/metrics-<mode>-<symbol>-<date>.jsonl`) і цикл котирування. Зупинка через settled/close-only зупиняє лише цей актив. Ліквідація, денний збиток і kill switch зупиняють усе.

Якщо актив не стартував (наприклад, через чужі ордери при `startup_cancel_all: false` або помилку перевірки лімітів), решта працює далі, а причину показує панель.

## Панель

`dry-run` і `start` піднімають локальну панель на [http://127.0.0.1:4320](http://127.0.0.1:4320) (`dashboard.port`, вимикається через `dashboard.enabled: false`). Вгорі — вкладки активів зі статусом, uptime і liquidity score. Кнопка «+ Додати актив» відкриває пошук по всіх інструментах біржі: вибраний актив проходить ті самі перевірки, що й на старті, і починає котируватися з сіткою з конфігу або налаштуваннями за замовчуванням. «Зняти з котирування» скасовує й перевіряє ордери лише цього активу. Вибір із панелі зберігається в `data/selection.json` і відновлюється при наступному запуску (`--from-config` повертає список із конфігу). Для вибраного активу видно режим (DRY-RUN або LIVE), статус і причину паузи, живу сітку з фактичними ордерами біржі, графік mid і власних котирувань за 10 хв зі смугою uptime, заповнення діапазонів відносно капу $100k, позицію, PnL акаунта з 12:00 UTC, події та алерти, стан потоків і dead man's switch. Сторінка оновлюється щосекунди.

Панель слухає лише loopback і перевіряє Host, Origin і `Sec-Fetch-Site`. Дії «Зупинити все», «Додати актив» і «Зняти з котирування» потребують токена процесу, JSON-тіла й підтвердження. «Зупинити все» виконує ту саму штатну зупинку, що й Ctrl+C. Ключів і секретів у відповідях панелі немає, події проходять через ту саму редакцію, що й логи.

Зупинка: кнопка на панелі, Ctrl+C, SIGTERM або файл `quoter/STOP`. Штатна зупинка для кожного активу виконує `cancelAll`, перевіряє `/open-orders` і лише потім вимикає `autoCancel`. Якщо процес упаде, біржа зніме ордери за дедлайном `autoCancel` (≤60 с).

## Налаштування

1. `copy config\example.yaml config\quoter.yaml` (файл у `.gitignore`). Головні поля: `instruments`, `levels`, `inventory`, `risk`.
2. Для live: `mode: live` і `operator.jurisdiction` / `operator.region`, тобто де ви фізично перебуваєте. Без них, а також для US, CA, CU, IR, KP, SY, Криму, Донецької й Луганської областей, `run --live` відмовить до будь-якого підпису. Країна проксі на це не впливає.
3. Ключі експортуються лише в оболонці. `.env` їх не приймає:

```powershell
$env:PERPS_OWNER_PRIVATE_KEY = '0x...'   # на старті реєструє proxy-ключ (TTL credentials.proxy_ttl_hours), тримає його в пам'яті
# або вже зареєстрований proxy-ключ:
$env:PERPS_PROXY_PRIVATE_KEY = '0x...'; $env:PERPS_PROXY_SECRET = '...'; $env:PERPS_PROXY_EXPIRES_AT = '1792500000000'
```

## Що робить live-цикл

Старт: синхронізація годинника, приватний WS (`orders`, `fills`, `portfolio`), два публічні потоки через різні проксі. Далі для кожного активу: перевірка інструмента й конфігу на ліміти, REST-знімок, `cancelAll` чужих ордерів (`risk.startup_cancel_all`) і плече. Лише після того, як хоча б один актив стартував, ставиться `autoCancel` +60 с з re-arm кожні 20 с. До цього активи стоять на паузі без ордерів, тож відмова на старті не чіпає таймер акаунта.

Кожна зміна mid (debounce `min_interval_ms`) проходить шлях QuoteEngine → RiskManager → Executor. Executor надсилає один батч на тип операції в порядку cancel → modify → place. Кожен підписаний запис робить одну спробу. Невизначений результат зупиняє записи до REST-звірки.

| Тригер | Дія |
|---|---|
| Стакан старший за `stale_book_ms` або обидва публічні потоки впали | `cancelAll`, пауза |
| Пропуск `sq` або перепідключення приватного потоку | заморозка, REST-звірка; заморозка довша за `max_freeze_s` (15 с) знімає котирування |
| Дедлайн `autoCancel` не продовжено двічі поспіль | `cancelAll`, пауза, доки дедлайн знову не підтверджено |
| Рух mid > `move_bps` за `window_s` | `cancelAll` на `pause_s` (або розширення сітки) |
| \|позиція\| ≥ `max_position_usd` | сторона, що збільшує позицію, не котирується (`zero`) або мінімальна (`shrink`) |
| Маржа < `min_available_margin_usd` | розміри пропорційно зменшуються |
| Ліквідація, денний PnL < −`max_daily_loss_usd`, settled/close-only, kill switch | `cancelAll`, зупинка процесу |
| Власний ордер поза своїм слотом (з'явився після перестановки) | скасовується |
| `post_only_rejected` N разів | слот відсувається на `ticks` на `for_s` |

Брейкер волатильності перевіряється раніше за будь-яку заморозку. Звірка з REST ніколи не перетинається з циклом котирування. Денний PnL рахується від вартості акаунта на 12:00 UTC: якір зберігається в `quoter/data/equity-anchor.json`, тож перезапуск не обнуляє ліміт збитку.

Метрики пишуться в `quoter/data/metrics-<mode>-<date>.jsonl`: uptime, середній liquidity score, notional по діапазонах, глибина чужого стакану по діапазонах, maker share з `/v1/account/stats`, оцінка raw score, обсяги, комісії. Dry-run-рядки мають `"simulated": true`.

## Обмеження

- Live-шлях перевірено лише проти локальної мок-біржі з перевіркою підписів. Реальних ордерів під час розробки не було. Перший live-крок за спекою: $1k на рівень.
- Семантика `sq` у приватних каналах не перевірена наживо: пропуск запускає REST-звірку, і вона ж повторюється кожні `reconcile_every_s`.
- Бот вважає інструмент своїм: пауза і зупинка виконують `cancelAll` на ньому, тож ручні ордери на тому самому інструменті теж будуть скасовані. `autoCancel` діє на весь акаунт.
- `status` і `cancel-all` з `PERPS_OWNER_PRIVATE_KEY` реєструють новий proxy-ключ. Щоб цього уникнути, передайте готовий `PERPS_PROXY_*`.
- Сесії акцій визначаються за розкладом NYSE без свят.
- Тунелі через проксі зрідка обриваються (1006). Публічні дані дубльовані, приватний потік перепідключається і звіряє стан, ордери на цей час заморожені, але лишаються в книзі.
